# 项目、知识库与 MCP Plan

状态：前后端已实现，后端集成测试、前端组件检查、浏览器回归、类型检查与生产构建已通过；临时测试文件按交付要求移除。发布须执行数据库迁移并切换已有知识库 MCP 客户端，见 [项目后端接入](project-backend.md)。

## 1. 目标与实现原则

完成项目、项目成员、知识库及项目 MCP 密钥的增删改查。一个用户可加入多个项目，知识库按项目隔离，密钥属于项目。

- 复用现有后台、业务服务、表单及客户端生成流程。
- 优先使用仓库已有 shadcn/ui 组件及默认 variants，保持当前 new-york、zinc、Lucide 配置。
- className 仅用于布局、间距、宽度和响应式；不覆盖组件颜色、字体、圆角、焦点或浮层层级，不更换主题。
- 不新增权限框架、Repository 层、全局状态库、万能资源管理器或兼容修复系统。
- 聊天前台与文件库入口继续隐藏；业务工具保留现有权限。

## 2. 表设计

| 表 | 字段与约束 |
| --- | --- |
| `project` 新增 | UUID 主键；name（100 字符，去首尾空白，唯一）；description（500 字符，可空）；创建/更新时间 |
| `project_member` 新增 | project_id、user_id 联合主键及外键；role 为 admin/member；加入时间 |
| `knowledge_base` 修改 | 必填 project_id 外键；名称改为 `(project_id, name)` 联合唯一 |
| `mcp_api_key` 修改 | 仅保留项目密钥，新增 project_id、created_by、permission（read_only/read_write）；沿用哈希、掩码、启停和时间字段 |

规则：

- 超级管理员沿用 user.is_superuser，不必加入每个项目。
- 文档、文件夹通过知识库确定项目，不重复保存 project_id。
- 项目密钥必须填写项目、创建人及权限；旧 internal/external 密钥在迁移时删除。
- created_by 仅记录来源，不参与授权；用户沿用软删除，创建人被移出、停用或软删除不影响项目密钥。
- 有知识库时禁止删除项目；空项目删除时清理成员关系和项目密钥。
- 移出成员不删除账号、资料或密钥。知识库与密钥不直接更换项目。
- 密钥明文仅创建时返回一次，数据库只保存哈希。

## 3. 权限

| 操作 | 超级管理员 | 项目管理员 | 普通成员 |
| --- | --- | --- | --- |
| 平台账号、项目创建/编辑/删除 | 允许 | 不允许 | 不允许 |
| 查看项目 | 全部 | 所属项目 | 所属项目 |
| 添加、移出普通成员 | 全部 | 所管理项目 | 不允许 |
| 设置角色、移出管理员 | 允许 | 不允许 | 不允许 |
| 维护知识库、文档、项目密钥 | 全部 | 所属项目 | 所属项目 |

项目管理员仅额外拥有成员添加、移出权限。添加成员直接选择已有账号，默认普通成员，不引入邀请审批。

MCP 只读仅开放已启用知识库列表和检索；读写允许完整知识库操作。项目密钥同时允许调用区域数据、B 站榜单、达人数据查询工具；不能管理账号、项目、成员。业务数据共用，不按项目隔离。

```text

  项目管理
  用户管理

  品牌营销
```

- 项目选择器只负责切换项目，不放管理入口；使用 Popover + Command，支持搜索和当前项勾选。
- 业务工具保持原有授权，无权限不显示。
- 平台管理在侧栏直接提供项目和用户两个入口；账号菜单保留外观及退出操作。

- 当前项目名称仅在侧栏显示；列表标题居中，详情面包屑为“知识库 / 产品资料”，保留现有“文档 / 搜索”Tabs、文件夹、上传、预览和分页。

- 继续搜索时保留已选用户；弹窗说明所属项目，确认按钮为“添加成员”。
- 超级管理员可调整项目角色；项目管理员只能移出普通成员。

### 4.4 MCP 接入

```text
             MCP 接入               ＋ 创建密钥

搜索密钥名称…                  权限 / 状态筛选  接入说明

名称          权限          状态      操作
```

- 左下角入口自动使用当前项目，不重复放项目选择器。
- 复用 KeyManager、密钥编辑弹窗与连接配置；项目内所有成员管理同一份密钥列表，不获得其他项目密钥的访问权。
- 创建 Dialog 填名称、权限，固定显示所属项目；默认只读。
- 成功后展示一次明文和可复制配置；后续只显示掩码。
- DropdownMenu 提供编辑名称和权限、启停、删除。
- 页面仅展示当前项目密钥；普通成员与超级管理员使用同一布局，无内部/外部分类。
- 搜索、权限/状态筛选与“接入说明”放在同一工具栏；接入说明展示一份配置和直接展开的工具列表。
- 只读仅开放已启用知识库列表、检索和平台业务数据查询；读写开放当前项目全部知识库工具。

### 4.5 平台管理

点击侧栏的“项目管理”或“用户管理”，直接进入对应页面：

```text
平台管理

搜索…                         ＋ 创建项目 / 创建用户
列表
```

- 两项管理入口在侧栏直接显示，页面内不再重复切换。
- 项目管理：Table 显示名称、成员数、知识库数；支持搜索、分页、进入、编辑、删除。
- 创建项目 Dialog 填名称、描述，可选初始管理员，允许空项目；成功后关闭弹窗并刷新列表，通过“进入”打开项目。
- 用户管理：复用现有账号列表、筛选和表单，支持创建、编辑、启停、删除；创建时可选多个项目及对应角色。
- 成员数、知识库数随项目列表查询返回，不为每行发请求，不新增计数字段。
- 页面标题不带项目名称，全局数据不受左上角项目选择影响；无需“返回项目资源”按钮，直接使用侧边栏。

### 4.6 搜索规范

| 位置 | 匹配字段 |
| --- | --- |
| 项目选择器 | 项目名称、描述 |
| 项目管理 | 项目名称、描述 |
| 知识库列表 | 当前项目的知识库名称、描述 |
| 项目成员、用户管理、添加成员 | 账号、姓名 |
| MCP 密钥 | 当前项目的密钥名称，不搜索明文 |

- 列表复用 SearchToolbar，由 Input 和搜索按钮组成，有明确的可访问名称。
- 停止输入约 300ms 后搜索，回车立即执行；中文输入法组词期间不提交。
- 使用已有防抖、Query 和 signal；分页列表由服务端搜索全部可访问数据，不只过滤当前页。
- Command 展示服务端结果时关闭本地二次过滤；候选列表复用普通加载更多按钮，不开发无限滚动组件。
- 清空搜索框移除关键词，筛选项切回“全部”移除该条件，均保留其他条件；关键词/筛选变化回第一页，不提供独立重置按钮，不展示匹配总数。
- 状态、角色等少量选项优先复用 ToggleGroup；窄布局可用 Select，不手写选中按钮样式。
- 搜索和筛选保存在 URL，输入更新用 replace，避免每个字符产生浏览器历史。
- 知识库内容检索只在点击搜索或回车时执行，不自动触发向量检索。
- 没结果使用 Empty，提示清除搜索/筛选；失败沿用 LoadError，保留输入并提供重试；请求中不禁用输入框。
- 第一版仅包含匹配，不增加拼音、纠错、全局搜索或搜索引擎。

### 4.7 状态与反馈

- 登录进入最近有权限项目的知识库；无记录取首个项目，无项目显示分配提示，超级管理员可进入平台管理创建。
- 项目/成员/MCP 之间切换保留当前项目；更换项目尽量保持功能，详情回到目标项目列表。
- 在平台管理或业务工具中选择项目时，进入目标项目知识库。
- 项目切换清除旧搜索、分页、选中项和密钥明文；编辑 Dialog 关闭后再切换，不新增全局导航拦截。
- 刷新和深链接恢复正确项目，面包屑与侧边栏一致；无权限显示现有错误状态，不自动猜测资源归属。
- 空知识库提供创建按钮；删除项目有知识库时提示先清空，允许删除时说明成员关系和密钥同步删除。
- 删除、移出使用 AlertDialog；加载使用 Skeleton/Spinner，状态使用 Badge，操作结果使用 Sonner。
- 移动端沿用折叠 Sidebar；表格沿用现有溢出处理。所有弹窗有标题，保留默认键盘、焦点及关闭行为。

## 5. 最小代码实现

### 前端路径与复用

```text
/admin                                     项目默认入口
/admin/knowledge-bases?projectId=...        原路径，项目列表上下文
/admin/knowledge-bases/[id]                 原详情路径，查询确定项目
/admin/projects/[projectId]/members         新增成员页
/admin/mcp?projectId=...                    原路径，项目 MCP
/admin/manage                              项目管理页
/admin/users                               用户管理页
```

- 项目管理和用户管理分别使用现有 ProjectManager、UserManager；旧 `/admin/manage?tab=users` 跳转到用户管理页。
- 项目列表和选择器共用接口，返回当前角色；后端操作仍实时授权。
- URL/已授权详情决定当前项目，本地只记忆最近项目；缓存键包含项目，跨项目不保留旧 placeholderData。
- 切换链接移除旧筛选参数，局部组件以 projectId 为 key 重置；不新增 store、手写竞态锁或逐项清理 effect。
- 组件优先复用仓库已有实现；缺少时使用 shadcn CLI 添加所需组件，不批量覆盖已定制的组件。
- 表单沿用 React Hook Form + Zod、FieldGroup/Field/FieldError；不封装万能表单或重做视觉体系。

### 后端与 MCP

- 新增 projects 模块，沿用现有分层；项目、成员共用模块，不拆重复服务。
- 后台用户与项目密钥分别认证，共用项目资源归属检查；覆盖详情、批量、上传、下载、预览及检索。
- 检查通用文件入口，不能通过 StoredFile.owner_id 绕过知识库项目权限。
- 上传服务只接收来源 UUID：后台传当前用户，MCP 传 created_by；它不参与授权，无需新服务账号或重构文件表。
- 新增 `/mcp/project`，注册知识库工具及明确开放的三个业务查询工具；复用现有业务服务，密钥确定项目，按操作检查读写权限，每次调用确认密钥状态。
- 仅保留项目 MCP；旧 internal/external 地址和密钥不再可用。客户端必须更换为项目地址和项目密钥，迁移 `000000000009` 会删除旧密钥。
- 创建项目及初始成员、创建用户及项目分配各用单事务；唯一约束、外键处理一致性，不加锁服务或重试框架。
- 复用现有文件解析、向量检索、清理及错误处理；不修改后台任务架构。
- API 更新后重新生成客户端，不手改生成文件。

## 6. 实施与验收

1. 新增迁移：建立项目/成员表和默认项目，回填知识库并收紧约束；现有用户不自动加入，文档 ID 与向量数据保留。
2. 实现项目/成员 CRUD、知识库授权、项目密钥与 MCP 适配。
3. 实现固定侧边栏、项目选择器、项目与用户管理入口、成员页面，复用知识库与 MCP 组件并接入搜索。
4. 生成客户端，运行后端检查、前端类型检查与构建，统一更新前后端和 MCP 配置。

关键验收：

- 多项目角色、跨项目单项/批量访问、上传/下载/检索均按权限执行。
- 只读不能写；创建人离开不影响密钥；已有连接中停用、删除、降权在后续调用生效。
- PostgreSQL 迁移、项目内名称唯一、非空项目删除限制、组合事务正确。
- 浏览器验证导航、项目切换、深链接、搜索/筛选/清除/返回、重名成员选择、CRUD 与密钥配置，无旧项目数据闪现。
- 权限、约束及流程已执行验证；临时测试文件按交付要求移除，不新增测试平台。
