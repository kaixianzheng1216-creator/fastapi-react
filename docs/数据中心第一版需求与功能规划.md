# 数据中心第一版 Plan

首版帮助用户完成营销准备中的具体工作：确定产品怎么讲、内容怎么做、找哪些作者、产品在海外怎么展示。数据中心提前准备可引用的资料，AI Agent 通过 MCP 查询后形成建议。先覆盖保温杯、充电宝、蓝牙耳机，验证同一套能力能否服务不同品类。

## 品牌营销：帮助用户确定产品的沟通重点

用户准备推广一款产品时，需要知道消费者在意什么、竞品已经在讲什么，以及自己的哪些卖点值得突出。首版围绕这三个问题提供依据。例如用户问“推广这款保温杯应该主打什么”，AI 先归纳收录评论中的购买顾虑，再查看同类产品的宣传表达，结合用户提供的真实产品信息，给出卖点方向和需要补充的证据。没有自家产品信息时，只提供品类洞察和待确认的问题。

这部分使用 JustOneAPI 的**笔记搜索 V4、详情 V1、评论 V2**，提前收录品类讨论和评论；需要参考海外商品表达时，复用 Dataify 的 **`amazon_product_by-url`**。笔记、评论按来源 ID 去重，过滤空白和明确广告，保留原文。程序只统计匹配笔记数、有效评论数及来源数，AI 负责归纳并引用证据。交付的是一份有出处的沟通建议，国内外样本分别说明，不把评论数量当成市场需求占比。

## 内容运营：帮助用户把推广方向变成可写的内容

用户有了推广方向，接下来要找到参考案例、决定具体选题，并把选题写成可执行的提纲。例如“帮我准备充电宝的下一批内容”，AI 可以从已收录笔记中找到相关表达方式，结合评论里尚未解释清楚的问题提出选题，再给出每个选题的开头、要点和需要用户补充的素材。用户拿到结果后能够开始创作。

数据复用 JustOneAPI 的**笔记搜索 V4 → 详情 V1 → 评论 V2**。入库保存标题、正文、作者、发布时间和链接，清理多余空白；缺正文的记录只作链接参考，不据此推断内容结构。MCP 按品类或关键词返回案例、评论和匹配数量，AI 在回答时组织选题与提纲。首版不建设独立选题库或“爆款”评分系统。

## 达人投放：帮助用户形成可人工筛选的合作名单

用户准备找作者合作时，先要找到做过同类内容的人，查看其最近作品，再比较几位候选的内容是否符合这次推广方向。例如“有哪些作者可以帮我介绍蓝牙耳机”，AI 返回候选主页、相关作品和选择理由，让用户据此决定进一步了解谁。首版解决合作前的资料筛选，不承诺作者愿意合作或能带来多少销售。

作者从已收录笔记中发现，再用 JustOneAPI 的**用户资料 V3、用户发布笔记 V4**补资料和作品，需要正文时复用详情 V1。按用户 ID 关联账号，按作品 ID 去重，避免昵称变化和重复采集影响结果。程序计算已收录的相关作品数，以及有效发布时间中的最近日期；AI 根据代表作品说明内容方向。列表不完整时显示覆盖情况，不把“未收录新作品”解释为停更，也不生成报价、受众画像或 ROI。

## 海外营销：帮助用户准备海外商品的销售页面

用户希望把产品卖到海外，首版先帮助其了解同类商品的报价、选择商品页的卖点表达，并补充买家关心的说明和 FAQ。例如“这款保温杯准备上架美国站，页面应该写什么”，AI 展示收录竞品的价格和配置，参考它们的商品描述与买家评论，给出页面内容建议。价格用于提供报价参考；最终定价仍需要用户自己的成本信息，文案也只能使用已确认的产品事实。

后台先用 Dataify 的 **`amazon_product_by-keywords`**发现商品链接，再用 **`amazon_product_by-url`**读取详情，用 **`amazon_comment_by-url`**补买家评论。根据[商店字段说明](https://www.dataify.com/products/scrapers/store/amazon_product_by-asin)，`asin/title/brand` 保存商品身份，`product_details/features/description/variations` 保留原始规格和卖点，`final_price/currency` 保存页面报价与币种。评论保存 `review_id/review_text/rating/review_posted_date`，关联 `asin/variant_asin`。

商品按站点和具体 ASIN 区分变体，规格先存 JSON 和原文，价格转十进制定点数；区间价、币种不明或解析失败保留原值，不强行计算。固定美国站和配送邮编，优惠券单独保留，不重复扣减。评论去重后只计算有效评论数和涉及商品数。AI 据这些资料做并列对比，不混算不同规格商品均价，也不把页面报价当成交价。

## 如何提前准备这些资料

四个领域共用上述数据。小红书统一用“品类名”“品类名＋推荐”“品类名＋测评”搜索；Amazon 使用 `insulated tumbler`、`power bank`、`wireless earbuds`。每词先取一页，排除无关内容和配件后收录，不需要预先维护品牌、作者或商品名单。

每品类暂以约 30 条图文、其中 5 条的评论、3 位作者、5 个商品及可得评论为目标。先用保温杯的小样本验证字段和清洗，再复用到另外两个品类。原始响应、来源 ID、品类、链接和采集时间一起保存，重复导入不能产生重复记录。数字或日期缺失留空，采集失败保留上次有效数据及其时间。

一份关键词配置和一个每周批处理任务即可启动，设置调用上限。MCP 查询内容、评论、作者和商品，限制返回条数并附来源、更新时间与覆盖说明。用户的问题不会触发外部采集；超出已覆盖范围时说明缺少哪些资料。以后增加品类先增加配置，暂不建设自动扩品类、复杂调度和规格标准化系统。

首版验收围绕业务结果：AI 能否据资料给出有出处的推广建议、可写的内容提纲、可查看的作者名单，以及海外商品页建议。接口字段不足时收窄对应结论，不用推测补齐。

## 接口依据

以下接口已核对公开文档或官方 SDK，尚未使用账号实测。小红书响应字段路径、Dataify 字段完整度及费用，以首批样本验证为准。

JustOneAPI：`GET https://api.justoneapi.com`，均需 `token`。

| 接口 | 路径 | 输入 |
| --- | --- | --- |
| [笔记搜索 V4](https://docs.justoneapi.com/zh/api/xiaohongshu-rednote/note-search-v4) | `/api/xiaohongshu/search-note/v4` | `keyword`、`page=1`、`noteType=NORMAL_NOTE` |
| [笔记详情 V1](https://docs.justoneapi.com/zh/api/xiaohongshu-rednote/note-details-v1) | `/api/xiaohongshu/get-note-detail/v1` | `noteId` |
| [笔记评论 V2](https://docs.justoneapi.com/zh/api/xiaohongshu-rednote/note-comments-v2) | `/api/xiaohongshu/get-note-comment/v2` | `noteId`、`sort=latest`；分页用 `lastCursor` |
| [用户资料 V3](https://docs.justoneapi.com/zh/api/xiaohongshu-rednote/user-profile-v3) | `/api/xiaohongshu/get-user/v3` | `userId` |
| [用户发布笔记 V4](https://docs.justoneapi.com/zh/api/xiaohongshu-rednote/user-published-notes-v4) | `/api/xiaohongshu/get-user-note-list/v4` | `userId`；分页用 `lastCursor` |

Dataify：[商品采集器源码](https://github.com/dataify-server/dataify-sdk-python/blob/main/src/dataify_sdk/tools/amazonproduct.py)、[评论采集器源码](https://github.com/dataify-server/dataify-sdk-python/blob/main/src/dataify_sdk/tools/amazoncomment.py)。

| 采集器 ID | 输入 | 用途 |
| --- | --- | --- |
| `amazon_product_by-keywords` | `keyword`、`page_turning=1` | 发现商品链接；显式处理价格筛选，避免误用 SDK 示例默认范围 |
| `amazon_product_by-url` | `url`、`zip_code=94107` | 固定美国站和配送邮编，采集商品详情与报价 |
| `amazon_comment_by-url` | `url` | 获取实际可得评论，不承诺全量或固定条数 |

Dataify 统一走后台任务：[客户端源码](https://github.com/dataify-server/dataify-sdk-python/blob/main/src/dataify_sdk/client.py)确认基址 `https://scraperapi.dataify.com`，`POST /builder?platform=1` 提交采集器与参数，`GET /task_status` 查状态，完成后 `GET /download` 下载入库。
