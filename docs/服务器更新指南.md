# 服务器更新指南

适用于原部署版本为 `e8783edd` 的 HTTP 测试服务器。你已执行 `git pull`，下面直接构建和部署，包含钉钉登录、项目邀请和成员退出。

以下命令在 Linux 服务器的项目根目录执行，逐条运行，**任意一条报错就停止**。统一使用 `-f compose.yml`，避免加载本地开发配置。使用 `stop` 停止全部服务，数据卷会保留。

## 1. 备份

```bash
backup="$HOME/fastapi-react-$(date +%Y%m%d-%H%M%S)"
docker compose -f compose.yml exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > "$backup.dump"
cp -p .env "$backup.env"
```

第一行设置带时间戳的备份路径；第二行导出数据库；第三行备份配置。文件保存在服务器用户主目录，确认导出成功后继续。

## 2. 修改配置

编辑服务器项目根目录 `.env`，填入测试环境配置，保留原有数据库密码及其他服务密钥：

```dotenv
ENVIRONMENT=local
DEV_LOGIN_ENABLED=false
APP_ORIGIN=http://你的测试服务器IP:3001
AUTH_SERVER_URL=https://测试统一认证服务地址
AUTH_SERVICE_TOKEN=测试环境的服务令牌
```

- `ENVIRONMENT=local` 允许测试服务器使用 HTTP；`DEV_LOGIN_ENABLED=false` 关闭本地模拟登录。
- `APP_ORIGIN` 必须填浏览器实际访问系统的地址，包含端口、不加 `/login`，不能写 `localhost`。登录回跳和邀请链接都会用它。
- `BACKEND_CORS_ORIGINS` 保留原值即可：当前浏览器请求前端，再由前端代理到后端，没有直接跨域访问后端。
- `frontend`、`backend`、`db`、`redis` 等容器内部服务名，以及健康检查里的 `localhost` 不用改。
- `AUTH_SERVER_URL` 和 `AUTH_SERVICE_TOKEN` 填认证服务提供的测试配置。请负责人将 `http://你的测试服务器IP:3001/login` 加入回跳白名单。

## 3. 更新

代码已经拉取，先构建镜像，成功后再停服务：

```bash
docker compose -f compose.yml build
```

`build` 将新代码构建成镜像；构建失败时先处理错误，旧服务仍可运行。

等正在处理的任务结束，再逐条执行：

```bash
# 停止全部服务
docker compose -f compose.yml stop

# 自动启动数据库并执行迁移
docker compose -f compose.yml run --rm prestart

# 使用本地 admin 已绑定的 auth_user_id，绑定服务器 admin
docker compose -f compose.yml run --rm --no-deps backend python -m scripts.bind_auth_admin --username admin --auth-user-id "41"

# 启动全部服务
docker compose -f compose.yml up -d
```

**已查询本地数据库：`admin` 的 `auth_user_id` 为 `41`，上面的命令已填入该值。** 这是统一用户 ID，不是用户名 `admin`，也不是用户表的 `id`。本地和服务器使用同一个测试认证服务时，沿用这个值；若认证环境不同，需要核实对应环境的统一用户 ID。

`--rm` 自动删除一次性容器，`-d` 表示后台运行。迁移命令会自动启动数据库，依次执行 `0011` 和 `0012`；管理员绑定复用已启动的数据库，所以加 `--no-deps`。最后 `up -d` 启动全部服务，即使再次运行迁移，也会跳过已完成的版本。

**迁移或管理员绑定失败，不要执行最后的启动命令。** 本次迁移会删除旧密码字段；回退旧版本需要恢复数据库备份，不能只回退代码。

## 4. 浏览器验收

通过 `http://你的测试服务器IP:3001` 验证：

- 钉钉登录成功，原管理员权限保留，页面没有本地模拟登录按钮。
- 创建邀请链接，确认链接使用测试服务器地址；另一个账号可以登录并加入项目。
- 普通成员可以在自己那行的操作菜单退出项目。

如果页面或登录异常，再执行以下排查命令，正常时不用运行：

```bash
docker compose -f compose.yml ps
docker compose -f compose.yml logs --tail=100 backend frontend prestart
```

`ps` 查看容器和健康状态，`logs` 查看最近的错误。一次性迁移容器执行后会被删除，迁移错误以第 3 步终端输出为准。

若反向代理设有路径白名单，还需放行 `/invite/*` 和 `/api/v1/invitations/*`。整站转发到前端的配置通常无需调整。

## 以后仅更新前端

只有确认后续变更仅涉及前端时，才使用：

```bash
git pull --ff-only origin master
docker compose -f compose.yml up -d --build --no-deps frontend
```

这两条命令更新代码并重建前端，不适用于本次包含数据库迁移的升级。
