# 品牌营销第一版 Plan

## 先解决“产品应该怎么讲”

用户准备推广产品时，往往不知道该突出什么。第一版帮助他弄清消费者在意什么、同类产品通常怎么表达，再结合自己的产品事实，形成一份有依据的沟通建议。用户看完后，应该能够决定本次推广重点，以及需要准备哪些证明材料。

例如用户问：“我有一款面向通勤人群的保温杯，准备在小红书推广，应该怎么讲？”AI 查询平台提前收录的笔记和评论，引用消费者的具体反馈与同类表达，再提出可供选择的沟通方向。如果用户尚未提供产品特点，先给品类观察，并说明还需要确认什么，不能替产品编造性能。

首版面向小红书营销，覆盖保温杯、充电宝、蓝牙耳机；开发时先用保温杯验证，再复用另外两个品类。当前不依赖客户名单或品牌授权数据。

## 提前准备哪些资料

这项业务先用 JustOneAPI 的三个接口即可。Dataify 的 Amazon 商品和评论适合后续海外市场分析，此处不把海外反馈混进国内推广依据，也无需为了同时使用两家平台增加采集流程。

| 资料如何取得 | 确认的接口 | 首次怎么调用 |
| --- | --- | --- |
| 发现品类讨论和同类表达 | [笔记搜索 V4](https://docs.justoneapi.com/zh/api/xiaohongshu-rednote/note-search-v4)，`/api/xiaohongshu/search-note/v4` | 分别传 `keyword=保温杯`、`保温杯 推荐`、`保温杯 测评`；`page=1`、`noteType=NORMAL_NOTE`、`sortType=general` |
| 保存可引用的内容 | [笔记详情 V1](https://docs.justoneapi.com/zh/api/xiaohongshu-rednote/note-details-v1)，`/api/xiaohongshu/get-note-detail/v1` | 用搜索取得的 `noteId` 补详情，首批目标约 30 条相关图文 |
| 理解购买顾虑和使用反馈 | [笔记评论 V2](https://docs.justoneapi.com/zh/api/xiaohongshu-rednote/note-comments-v2)，`/api/xiaohongshu/get-note-comment/v2` | 从不同作者的约 5 条笔记各取一页，传 `noteId`、`sort=latest`；需要补页时才用 `lastCursor` |

以上均为 `GET https://api.justoneapi.com` 加接口路径，请求需 `token`。接口存在和输入已核对，实际账号权限、返回字段路径与费用仍需小样本验证。

只收录与品类相关的内容，排除无关结果，保留搜索词、来源链接和采集时间。品牌和型号从原文明确提及的信息中发现，不要求开发者事先研究竞品名单。普通用户笔记中的表达只能称“同类产品的内容表达”；来源未经确认时，不能称品牌官方宣传。

## 怎样把资料变成可用的依据

保存笔记 ID、标题、正文、作者 ID、发布时间，以及关联的评论 ID、正文和时间，同时保留原始响应。按平台和原始 ID 去重，清理空白及明确广告；没有正文不参与正文归纳，没有日期不参与时间筛选。实际字段映射在首次接入时确定。

首版只做关键词检索和简单计数。匹配笔记数按不同笔记 ID 计算，评论数按去重后的有效评论计算，并返回评论来自多少条笔记。它们用于说明证据覆盖，不用于评判品牌声量或需求规模。每个词只取少量搜索结果，也不能据此判断全平台最常见的顾虑。

平台通过一个只读 MCP 查询入口返回某品类的笔记与关联评论，允许进一步按关键词筛选，限制返回数量并带上原文、链接和时间。计数注明是查询匹配总数还是本次返回数。AI 只归纳实际读到的资料，不把一页结果当成全部样本。

用户的产品事实随提问提供即可，不先建设产品管理系统。AI 将评论中的顾虑、同类内容的表达与用户提供的事实对照，形成建议；缺证据的产品卖点列为待确认项。首版不需要后台主题分类、情感打分或复杂标签体系。

## 用户最终拿到什么

交付是一份简短的品牌沟通建议。它先说明收录消费者反馈中值得回应的问题，并附原话；接着展示同类内容如何表达，帮助用户理解常见说法；最后给出两三个适合其产品事实的沟通方向，说明每个方向应准备的证明材料。

例如，如果样本中确实出现“放进包里会不会漏”的疑问，而用户确认产品有对应的防漏设计，AI 可以建议围绕携带场景组织表达，并提醒补充可验证的展示材料。这只是说明建议如何产生，是否采用该方向取决于真实评论和产品信息。

这三个部分分别解决消费者顾虑、同类表达和自身沟通重点的问题。来源不足时说明不足，不承诺找出市场空白、最优定位或销售效果。

## 一个人怎么推进

先做一次后台手动采集：保温杯取约 10 条笔记，其中 3 条补评论。验证正文可读、评论能关联、重复导入不会重复计数后，接上 MCP，用自己的假设产品资料走一遍完整问答；假设信息须明确标注。

验收时看回答能否帮助选择沟通方向：每条消费者观察是否有可打开的原文，建议是否符合输入的产品事实，信息不足时是否明确指出缺口。没有客户时，这一步验证的是功能可用性，不代表市场需求已经验证。

这条流程跑通后，再扩大到约 30 条笔记，并复用到充电宝和蓝牙耳机。最后加一个每周批处理任务，用时间排序发现新笔记，设定调用上限；失败保留上次有效数据和时间。用户通过 MCP 查询时始终读取已入库资料，不触发临时采集。后续新增品类先增加关键词配置，暂不开发其他营销领域。
