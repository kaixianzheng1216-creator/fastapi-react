**第一版先做“每日更新的笔记研究库”，再用真实采集结果验证关键词趋势。**

1. **先验证数据来源**
   用少量主题试采 JustOneAPI，确认能获取哪些字段、每天能发现多少不同笔记、能否更新已有笔记。重点判断：笔记数量是否主要受分页和采集配额限制。

2. **先上线笔记模块**
   - **笔记搜索**：搜索已入库内容，按时间、图文/视频和互动指标筛选。
   - **热门笔记**：查看采集样本中互动较高的笔记。
   - **笔记详情**：正文、标签、原文链接、基础指标及更新时间。

3. **每天积累数据**
   定时发现笔记、按 ID 去重、刷新计数、保存每日快照。优先使用原始话题标签组织内容，不用 AI，不做逐篇人工分类。

4. **关键词先做研究入口**
   点击标签可以查看相关笔记、每日收录数量、共同出现的话题。**关联笔记数用于说明样本，不急着把它包装成热度。**

5. **有可靠依据后再开放趋势榜**
   验证采集范围稳定、周期可比，再决定热门关键词和增长关键词的排名规则。如果数量主要由采集配额决定，就暂不上榜。

6. **通过 MCP 提供同一套查询**
   先提供笔记搜索、笔记详情、关键词相关笔记查询；趋势成立后再增加趋势工具。网页与 MCP 共用统计口径。

**第一版菜单建议：**

```text
笔记
├── 笔记搜索
└── 热门笔记

趋势（验证后开放）
├── 热门关键词
└── 增长关键词
```

**第一步交付物：一批真实笔记样本、一张可用字段表、一份每日采集成本估算。用它们确定页面能力，再开始正式开发。**
